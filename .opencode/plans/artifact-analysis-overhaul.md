# Artifact Analysis Overhaul

Replace the pricing-specific analysis pipeline with a generic artifact analysis system. All personas simulate through five invariant cognitive stages. The report shifts from scoring to evidence.

## Entity Hierarchy

```
ArtifactAnalysis (the run / container)
├── status: AnalysisStatus
├── artifactType: 'url' | 'screenshot'
├── artifactUrl?: string
├── businessGoal: string
├── researchQuestion: string
├── responses: PersonaResponse[]
└── ...

PersonaResponse (one persona's output)
├── personaProfile
├── personaId
├── rawAnalysis: string           (full 5-stage reasoning trace)
├── customerJourney: StageJourney[]
│   ├── Interpretation
│   ├── Understanding
│   ├── Belief
│   ├── Motivation
│   └── Action
├── researchQuestionAnswer: string
├── majorFindings: MajorFinding[]
├── pointsOfFriction: string[]
├── unansweredQuestions: string[]
├── overview: string
└── ...
```

Every `PersonaResponse` has all five stages. A stage can succeed, fail, block, or stop. No missing stages.

## Cognitive Stages

| # | Stage | Core Question |
|---|-------|--------------|
| 1 | Interpretation | What do I think this is? |
| 2 | Understanding | Do I understand it? |
| 3 | Belief | Do I believe it? |
| 4 | Motivation | Do I care enough? |
| 5 | Action | What do I do? |

## MajorFinding

```typescript
interface MajorFinding {
  observation: string;   // What happened
  evidence: string;      // What personas experienced
  impact: string;        // Why it matters
  confidence: 'High' | 'Medium' | 'Low';  // Derived from inter-persona agreement
}
```

## Invariants

- `PersonaResponse` is one persona's output, never aggregate
- `ArtifactAnalysis` is the container for a run, never per-persona
- All prompts are artifact-agnostic — no mention of pricing, conversion, or page types
- Confidence is derived from observed agreement, never generated by the LLM
- Intake strategies are decoupled from analysis pipeline
- Old IndexedDB data is wiped on first load
- No pricing-specific fields survive in domain entities
- Each phase produces a commit and is reviewed before the next phase begins
- The two-stage pipeline (stream of consciousness → structured format) stays — only the prompts and output schema change

## Architecture (Before → After)

### Before

```
URL/Screenshot → Browser scouting for PRICING → Persona evaluates pricing
  → Output: [The Good]/[The Bad]/[The Dealbreaker] + 6 numeric scores + risks + recs + AI suggestion
```

### After

```
Artifact → Intake Strategy (browser or direct-pass) → Contextualized artifact
  → Persona simulates through 5 cognitive stages:
    1. What do I think this is?
    2. Do I understand it?
    3. Do I believe it?
    4. Do I care enough?
    5. What do I do?
  → Output: Stage journey + major findings + friction + unanswered questions + research answer
```

Intake strategies are pluggable. Adding PDF support later means writing `PdfIntakeStrategy`, not touching the analysis pipeline.

## Review Subagent Prompt

After each phase commits, spawn a subagent with:

> You are a skeptical senior developer reviewing a commit.
>
> **There are definitely issues in this code.** Specifically:
>
> 1. **Logic errors** — find them. The code does something different from what the plan intended.
> 2. **Error handling gaps** — errors are not caught gracefully, not propagated, or not surfaced to the user in the UI.
> 3. **Bugs** — edge cases, null references, race conditions, type mismatches.
> 4. **Code quality / Shugi violations** — unnecessary complexity, poor naming, missing invariants, framework leaks into domain, coupling that should not exist.
>
> Read the diff carefully. Reject anything that does not follow the Shugi (reduce complexity, optimize for the next engineer, localize complexity, etc.).
>
> Respond with:
> - Approval (no issues found)
> - Conditional approval (minor issues listed, can be fixed in next phase)
> - Blocked (issues that must be fixed before proceeding)
